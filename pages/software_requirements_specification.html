3. External Interface Requirements

3.1 User Interfaces

The Culinary Preferences Organizer website interacts with three main user groups: individuals, groups and administrators. Individuals and groups are people who want to benefit from the website's functionalities and administrators are responsible for modifying the database. Users will be required to create an account and log in to access the website's features.

The website's user interface is designed to follow industry-standard web design principles and best practices. The layout is intuitive, with easy-to-use navigation and clear calls-to-action. The site's design is consistent across all pages, with a header that includes the site's logo and a sign-out button that returns the user to the login page.

The user interface is web-based, and is designed to be responsive and accessible across a range of devices and screen sizes. The site includes standard buttons and functions, such as a home button and navigation buttons, as well as keyboard shortcuts and other accessibility features as needed.

The user interface is designed to meet accessibility standards and ensure that all users can access the site's content and features, regardless of their abilities. In addition, the website complies with relevant data privacy regulations to ensure that user data is protected.

3.2 Hardware Interfaces

The Culinary Preferences Organizer website does not have any specific hardware requirements and can run on any device that has a web browser and an internet connection. The software does not interact with any specific hardware components and is not dependent on any particular hardware communication protocols.

3.3 Software Interfaces

The Culinary Preferences Organizer website interacts with a database where information about the users is stored, including their email address, password, name, other specific information about them, and their culinary preferences. This database is used for the login component and for creating the statistics.

The website is built using HTML, CSS and PHP and interacts with the database using SQL queries. The website does not interact with any other specific software components or libraries.

To access the database, the website connects to it using the appropriate credentials and communication protocols. The data items that are exchanged between the website and the database include user login information and user profile information. The purpose of each data item is to facilitate user authentication and personalize the user experience.

3.4 Communications Interfaces

The Culinary Preferences Organizer website requires communication functions to enable user interactions such as email notifications and feedback submissions. The following communication protocols and standards are used:

  • Email: The website sends email notifications to users to confirm their account creation and password reset requests. The email protocol used is SMTP.
  • Web Browser: The website interacts with web browsers to deliver its content to users. The supported web browsers are Chrome, Firefox, Safari and Edge. The website follows web standards such as HTML5 and CSS3 to ensure compatibility across different web browsers.
  • HTTP: The website uses HTTP protocol for communication between the web server and client web browsers.
  • HTTPS: The website uses HTTPS protocol to encrypt and secure data transmission between the web server and client web browsers.

In addition, the website complies with data privacy and security regulations such as GDPR and CCPA. Any data collected from users is stored securely and is not shared with third-party services without user consent. Any communication security or encryption issues are addressed using industry-standard encryption protocols.

4. System Features

4.1 User Registration and Authentication

4.1.1 Description and Priority

User can create an account and log in to manage their culinary preferences, dietary restrictions, and other related information. This feature is of High priority as it forms the core functionality of the application, directly impacting user experience and satisfaction.

4.1.2 Stimulus/Response Sequences

  • The user enters login credentials and hit the Log in button.
  • The system receives login credentials for verification and check it.
  • If the user has entered correct data, he gets access to his profile page.
  • If the user entered incorrect data, the system informs the user about this and allows to try again.

4.1.3 Functional Requirements

  • The system should provide a user with a registration form.
  • The system should allow the user to choose which type of account to create (individual or group).
  • The system should check whether the login matches the email template.
  • The system should inform the user how to create a strong password.
  • The system must store credentials in a secure database
  • The system musn't provide access to the user's personal data without correctly entered credentials.
  • The system must allow the user to delete the account.
  • The system should allow the user to enter additional information such as age, allergies, nationality etc.
  • The system should allow the user to change the nickname or the password.
  • The system must allow the user to log out of the account.

4.2 User and global statistics.

4.2.1 Description and Priority

A verified user will be able to view personalized and global statistics. This feature is of high priority.

4.2.2 Stimulus/Response Sequences

  • The user opens the home page.
  • User clicks on "See statistics" button in the main page.
  • The system provides two buttons "See global statistics" and "See personalized statistics".
  • The user chooses one of two options.
  • The system displays statistics according to the user's choice.

4.2.3 Functional Requirements

  • The system should display statistics with correct data.
  • The system must not provide a user with access to personalized statistics of another user.
  • The system should display statistics in an understandable form.
  • The system should provide an opportunity to save statistics in a CSV and PDF formats.

4.3 Creating a shopping list

4.3.1 Description and Priority

The user can create a personal shopping list consisting of individually selected products. This feature is of high priority.

4.3.2 Stimulus/Response Sequences

  • The user opens the home page.
  • User clicks on "Create a shopping list" button in the main page.
  • The system displays a page where the user can add and remove fields for list items.
  • The user clicks the "+" button to display a new text box for the list item.
  • The user clicks the "Save" button and the system saves the shopping list in PDF format.

4.3.3 Functional Requirements

  1. The system should allow the user to save the list in PDF format.
  2. The system should provide additional information about products (shelf life, availability depending on season, geographic region etc.).
  3. The system should personally select products for the user.
  4. The system should allow the user to add and remove fields for entering list items.
  5. The system should display the list created by the user on the page.

4.4 Food search

4.4.1 Description and Priority

The user can search for a specific dish on the home page and get detailed information about it. This feature is of high priority.

4.4.2 Stimulus/Response Sequences

  1. The user opens the home page.
  2. The user clicks on the search bar.
  3. The user enters the name of the dish to be found.
  4. The system finds this dish and displays detailed information about the dish, if such a dish is not found, the system notifies about it.

4.4.3 Functional Requirements

  1. The system should output the appropriate dish.
  2. The system should provide detailed information about the dish.
  3. The system needs to notify the user if such a dish is not found.

4.5 Admin Management

4.4.1 Description and Priority

The system has an administrator who can manipulate data from the database. This feature is of high priority.

4.4.2 Stimulus/Response Sequences

  1. Admin enters login credentials and hit the Log in button.
  2. The system receives login credentials for verification and check it.
  3. If the admin has entered correct data, he gets access to his profile page.
  4. Admin gets access to admin account and database

4.4.3 Functional Requirements

  1. The system must reliably verify the admin.
  2. The system should allow the administrator to delete the account.
  3. The system must allow the admin to log out of the account.
  4. The system should allow the administrator to manipulate the database (viewing the database and deleting users)
  5. The system must ensure that the database remains consistent when admin delete users.
  6. The system must notify the administrator about the result of the administrator's request to delete the user (successfully or an error occurred).

5. Other Nonfunctional Requirements

5.1 Performance Requirements

The web application must perform efficiently to handle REST/GraphQL API requests seamlessly. Response times for API calls should be within acceptable limits to ensure a smooth user experience. The system must be capable of handling large volumes of data from Open Food Facts and related metadata without compromising performance. It should efficiently manage various data types such as category, price, ingredients, images, restrictions, perishability, shelf life, availability, and restaurant information. The application's functionality for creating shopping lists and user administration tasks should execute swiftly. Furthermore, the generation of statistics and exporting them in open formats like CSV and PDF must be performed efficiently to facilitate data analysis and sharing.

5.2 Safety Requirements

The software must prioritize data security and user privacy by implementing relaible authentication and access controls to safeguard sensitive information, including personal culinary preferences and dietary restrictions.

5.3 Security Requirements

Cryption will be applied to passwords, ensuring each user's account security by preventing unauthorized access.

The system should check the role and grant privileges to the user accordingly, thus data security will be achieved.

5.4 Software Quality Attributes

The system accesses through the Food Open Facts API information that is updated and maintained, so the program remains flexible to changes in the environment.

The system will have a clear interface to maximize intuitive understanding by the user.

6. Other Requirements

6.1 Database Requirements

In order for the system to work efficiently, we will use a relational database in which the tables will be connected using primary keys.

6.2 Internationalization Requirements

Our system is designed to be used by different people from different countries, so it is important to use English because it is the international language of communication.

6.3 Legal Requirements

Our system uses sensitive information, such as allergies and human characteristics, and therefore it will not be published or used for other purposes that do not coincide with the purposes of the system described above.

6.4 Appendix A: Glossary

  • HTML5 = Hyper Text Markup Language
    • HTML is the standardized markup language utilized for crafting Web pages
    • HTML provides a structural framework for web documents, defining the layout and organization of content.
    • HTML elements are used to specify how content should be presented on a web page
    • HTML enables the creation of hyperlinks, allowing users to navigate between different web pages and resources.
    • HTML5 represents the fifth and concluding major iteration of HTML, acknowledged as a recommendation by the World Wide Web Consortium (W3C)
  • CSS = Cascading Style Sheets
    • CSS allows web designers to control the presentation of web pages, including elements such as fonts, colors, spacing, and layout.
    • CSS enables designers to control the layout of web pages, specifying the positioning and arrangement of elements such as text, images, and navigation menus.
    • CSS provides flexibility in design, allowing developers to easily modify the appearance of a website without altering its underlying HTML structure.
  • PHP = PHP: Hypertext Preprocessor
    • PHP enables the generation of dynamic page content
    • PHP facilitates operations like creating, opening, reading, writing, deleting, and closing files on the server
    • PHP can handle form data submission
    • PHP can manage cookies for sending and receiving data
    • PHP allows for manipulation of data in databases, including addition, deletion, and modification
    • PHP can be utilized for user-access control
    • PHP offers encryption capabilities for data security
  • SQL = Structured Query Language
    • SQL facilitates the querying and manipulation of databases
